# Like Counts (record of what was built)

Built 2026-09-23 on the owner's request. This is a record of the design and its limits, not a step-by-step plan.

**Goal:** Readers can like a post or project and see the count, without giving up the static site.

**Principle:** content is written by the owner, rarely, and needs history, so it stays in git. Likes are written by anonymous readers, often, and need no history, so they go to a small database. The site must stay complete without the counter: with no `NEXT_PUBLIC_LIKES_API` at build time, or when the Worker is unreachable, the button is not rendered and nothing else changes.

## Pieces

- `workers/likes/`: a Cloudflare Worker with its own `package.json` and `wrangler.toml`, outside the Next build.
  - `src/handler.ts`: pure request handling, with the store injected; tests in `handler.test.ts`.
  - `src/d1-store.ts`: the D1 store.
  - `src/index.ts`: wiring.
  - `migrations/0001_init.sql`: the tables.
- API:
  - `GET /likes?id=<kind>/<category>/<slug>` returns `{ n }`.
  - `POST /likes` with `{ id }` returns `{ n, counted }`.
  - The id is `likeId()` in `lib/share-paths.ts`. It has no language, so `/en/` and `/zh/` share one count.
- Limits: one counted like per id per visitor per 24h. A visitor is a SHA-256 of the IP with the `VOTER_SALT` secret; raw IPs are never stored. Vote rows older than the window are pruned on each like. Increments are a single upsert inside a batch, so they are atomic.
- CORS and origin: only origins in `ALLOWED_ORIGINS` get CORS headers, and requests carrying any other `Origin` get 403.
- `components/shared/LikeButton.tsx`: a heart tile in the share row on blog and portfolio detail pages.
  - Fetches the count on mount; the click is optimistic, then POSTs.
  - Remembers "liked" in `localStorage` (inside try/catch), and the server-side limit still applies.
- CI: the repository variable `LIKES_API_URL` becomes `NEXT_PUBLIC_LIKES_API` in `.github/workflows/deploy.yml`.

## Known limits

- The counter is not proof against a determined person: changing IP resets the daily limit. This is acceptable for a personal site.
- `*.workers.dev` is not reachable from mainland China. Readers there don't see the button, and nothing breaks. Serving the Worker from a custom domain would fix this.
- Counts are not in the static HTML; they appear once the fetch returns.

## Verification done (2026-09-23)

- `npx vitest run workers`: handler tests (counting, daily limit, origin checks, bad input, preflight, voter hashing).
- `wrangler dev` with local D1, checked with curl: GET 0 → POST counted → repeat POST not counted → other origin 403 → preflight CORS.
- Static build with the local API, in Chrome:
  - Liking on `/zh/.../resident-evil-review/` changes the label to 已赞 with count 1.
  - `/en/` of the same post shows Liked with 1.
  - With the Worker stopped, the button is gone and Share still works.
