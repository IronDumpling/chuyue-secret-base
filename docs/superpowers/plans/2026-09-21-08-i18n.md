# 计划 08：中英文双语（默认英文），排在手机编辑器（计划 03）之前

## 为什么现在做这个

你决定网站需要中文和英文两个版本，默认英文，整个界面都要有两种语言。这会改变内容文件的结构和所有页面的网址，而计划 03（手机编辑器）的表单、文件夹、图片路径都建立在这个结构上，所以先做中英文，再做编辑器，避免返工。路线图顺序变为：**02（已上线）→ 08 中英文 → 03 手机编辑器 → 04 分享海报 → 05 RSS/统计 → 06 Shutterstock**。

## 你已经确认的决定

1. **默认语言：英文。** 现有 46 篇内容本来就是英文，所以默认语言下所有内容都完整，没有"缺翻译"的提示。
2. **网址：** `/zh/...` 和 `/en/...` 两套对称的网址，根网址 `/` 跳转到英文（`/en/`；如果访客之前在页面上选过中文，则跳到 `/zh/`）。
   这推翻了路线图里"已有网址永不改变"的原则，所以旧网址要保留成"跳转页"（见任务 4），已经分享出去的链接才不会 404。旧网址的内容本来就是英文，所以它们跳到 `/en/...`，语言不变。
3. **正文：** 每篇文章、每个项目可以有中文和英文两个版本；缺哪个语言，就显示另一个语言的版本，并在页面上标注（例如中文页缺中文版时："暂无中文版，以下为英文原文"）。不强迫一次翻译现有 46 篇；在 `/zh/` 下这 46 篇会显示这个提示，直到你补上中文版。
4. **界面：** 导航、页脚、首页各区块、关于/经历/技能/联系、博客和作品集的列表与详情页的所有固定文字，都有中英两版。

## 现状（已核对）

- 页面都在 `app/` 下且没有语言层级；`app/layout.tsx` 写死 `<html lang="en">`。
- 固定文字大量硬编码在组件里：`ExperiencesSection` 364 行、`SkillsSection` 345 行、`AboutSection` 277 行、`Header` 211 行、`ContactSection` 159 行、`PortfolioSection`、`BlogSection`、`Footer` 等，另有 `lib/identity.ts`、`lib/blog-utils.ts`、`lib/portfolio-utils.ts` 里的标签。
- 内部链接约 31 处写死成 `/blog`、`/#home-section` 这样的形式；`Header` 的滚动高亮逻辑写死 `pathname !== '/'`。
- 内容文件：`content/blog/<分类>/<类型>/<slug>.mdx`、`content/portfolio/<分类>/<slug>.mdx`，现在全是英文，frontmatter 里已有 `category`/`type` 字段（站点加载时会用文件夹覆盖它们）。
- 计划 02 的分享卡片路径是 `/share/og/blog/...`，页面 canonical、sitemap 都是不带语言的。

## 方案

- **不引入 i18n 库。** 用 `app/[lang]/` 路由段 + 一个带类型的小词典：英文词典 `en.ts` 定义类型，中文词典 `zh.ts` 必须满足同一个类型，少一个 key 编译就报错。客户端组件用 `useT()`，服务端组件直接取词典。
- **语言从网址来。** `generateStaticParams` 返回 `zh`、`en`，`dynamicParams = false`；`<html lang>` 由 `app/[lang]/layout.tsx` 设置，对爬虫也正确。
- **内容文件命名：** `slug.zh.mdx`、`slug.en.mdx`（同一个 slug，网址里的 slug 不变）。没有后缀的旧文件按英文处理，所以现有 46 个文件**不用改名**，站点先兼容两种写法，旧内容原样可用。这个命名也正好是 Sveltia CMS 的多语言默认格式（计划 03 用）。
- **旧网址不 404：** 保留 `/blog/...`、`/portfolio/...`、`/contact/` 等旧路径，生成很小的跳转页（脚本 `location.replace` + `<noscript>` 里的 meta refresh + 一个可点的链接），目标是同一页面的 `/en/...`，并带上 og 标签，这样已经发出去的链接预览也还能显示。GitHub Pages 不能做服务端 301，只能这样。
- **两个根布局：** `app/[lang]/layout.tsx`（正式页面）和 `app/(legacy)/layout.tsx`（根跳转和旧网址跳转页）。任务 4 第一步先用最小示例验证静态导出能这样构建，不行再换方案（例如所有页面共用一个根布局，`lang` 用请求头之外的方式设置）。
- **语言切换：** 头部加 `中 / EN` 切换，跳到同一页面的另一种语言，并把选择记在 `localStorage`；根网址的跳转读取它，没有记录就去 `/en/`。

## 风险和已知限制

- **旧链接靠前端跳转。** GitHub Pages 不能做 301，搜索引擎需要一段时间才会把旧网址换成新的；跳转页里的 canonical 指向新网址来加快这个过程。
- **所有现有网址都迁到 `/en/` 下，** 这是你确认过的取舍（默认英文后，内容和语言都没变，只是多了 `/en/` 前缀）。已发出去的分享卡片缓存里保存的是旧网址，靠跳转页兜底。
- **双根布局**在 Next.js 里跨布局跳转会整页刷新，只影响旧网址和根网址（都是一次性跳转），正式页面之间不受影响。
- **构建变慢：** 分享卡片翻倍（约 94 张），预计再多 15–30 秒。
- **中文文案的质量取决于你的审阅。** 我起草的翻译尤其在个人叙述部分需要你改成自己的口吻。
- 现有 46 篇内容仍然是英文，在 `/zh/` 下会显示提示条；翻译哪一篇由你决定（计划 03 的编辑器上线后可以在手机上补中文版）。
